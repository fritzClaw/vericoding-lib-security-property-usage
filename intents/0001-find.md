# 0001-find — `vfind`: a verified, injection-safe `find` (listing only)

## Intent

A command-line tool `vfind` that, like Unix `find` without an expression,
lists every file and directory under the given start paths, recursively, one
path per line. Unlike GNU `find`, its output is **safe to count and to parse**:
a file name can never split a line or forge an extra path, so
`vfind DIR | wc -l` is exactly the number of listed paths and the output
decodes back to exactly the listed paths. Order is deterministic, symlink
loops and bind-mount loops can't make it run forever, and every traversal
decision is made by verified code.

## Interface

- Binary `vfind`, usage `vfind [-L] [PATH...]`.
- Verified core (pure, in `src/lib.rs`): decides every stdout byte, every
  stderr line, the exit code, and every traversal decision (which path to
  look at, which directory to enter, in which order, loop detection).
- Trusted shell (`// <vc-shell>` in `src/main.rs`): parses argv, answers the
  core's two questions about the filesystem, and writes bytes:
  - **look at PATH** → `Missing(msg)`, or an entry with a *kind*
    (directory / symlink / other) and an *identity* (device + inode).
    Without `-L` the shell uses `lstat`; with `-L` it uses `stat`, falling back
    to `lstat` for a broken symlink (kind symlink).
  - **list directory PATH** → its entry names (raw bytes), or `Unreadable(msg)`.
- Names and paths are raw bytes (`Vec<u8>`); non-UTF-8 is fine.

## Decisions

| #   | Question | Decision | Spec clause |
|-----|----------|----------|-------------|
| D1  | Scope? | Listing only: `vfind [-L] [PATH...]`. No tests or expressions (`-name`, `-type`, operators), no `-H`, `-print0`, `-depth`, `-maxdepth`. | request type |
| D2  | Binary name? | `vfind`: doesn't shadow the system `find`; its output format deliberately differs (D13). | — (crate) |
| D3  | Proved vs trusted? | The core drives the walk (see Interface). The shell only answers "look at" / "list directory" queries, parses argv and prints. Trusted: the filesystem doesn't change during the run and the shell answers faithfully. | `run` ensures, over an abstract filesystem model |
| D4  | Order? | Pre-order: a directory is printed before its contents. Siblings sorted by raw byte order of the name (shorter prefix first), **before** escaping. Start paths in argv order. | `sorted_bytewise`, walk spec |
| D5  | Start paths? | No path → `.`. Several → walked in argv order; duplicates walked again. Each start path is printed as typed (depth 0). | walk spec |
| D6  | Child path? | Parent path + `/` + name; no extra `/` if the parent ends in `/` (`vfind t/` prints `t/a`, not `t//a`). Robust core *(agent proposal, confirmed with the intent)*: within one directory the core ignores entry names that are empty, `.`, `..` or contain `/`, and collapses duplicate names. The OS never yields these; ignoring them guarantees a path can't be forged one level deeper. | dir entries filter |
| D7  | Dotfiles? | Listed like any other name. `.`/`..` entries never (D6). | D6 |
| D8  | Symlinks without `-L`? | Printed, never entered, including a start path that is a symlink to a directory (pure `-P`; no `-H`). | kind from `lstat` |
| D9  | `-L`? | Every symlink is followed (start paths too): the entry's kind and identity are its target's. A broken symlink is printed, not entered, not an error. | kind from `stat` |
| D10 | Loops? | **Always** (with or without `-L`): before entering a directory whose identity equals the identity of a directory on its own ancestor chain (start path included), the path is printed but not entered, stderr gets one line `vfind: filesystem loop: PATH`, and the exit status becomes 1. A directory reached by two different non-ancestor paths (e.g. a symlink to a sibling under `-L`) is listed under each. | loop rule |
| D11 | Missing start path? | Nothing on stdout for it; stderr `vfind: PATH: MSG`; exit status 1; continue with the next start path. | error rule |
| D12 | Unreadable directory? | The directory's path is printed, its contents aren't; stderr `vfind: PATH: MSG`; exit status 1; continue. | error rule |
| D13 | How is a path written? | Codec `security_property::BackslashEscape`: `\` → `\\`, LF → `\n`, TAB → `\t`, `:` → `\:`, printable ASCII as itself, every other byte → `\xHH` (lowercase); delimiter LF, marker `:`. stdout **equals** `unparse_records::<BackslashEscape>(printed paths)`: each path escaped, followed by LF. | link: stdout == `unparse_records` |
| D14 | Can data split a record? | No: number of LF bytes in stdout == number of printed paths. | `theorem_record_count` |
| D15 | Can data forge a path? | No: the stdout bytes determine the list of printed paths (injective unparser, parse(unparse(x)) = x). | `theorem_records_injective` |
| D16 | Decoding? | No decoder in `vfind`. Consumers decode with the library's strict `decode_records::<BackslashEscape>`. | library contract |
| D17 | stderr format? | One line per error, in traversal order: `vfind: ` + escaped PATH + `: ` + escaped MSG + LF, or `vfind: filesystem loop: ` + escaped PATH + LF. MSG is the OS error text from the shell. | stderr spec |
| D18 | Exit status? | 0 if no error occurred, else 1. | exit spec |
| D19 | Argv? | Leading `-L` (repeatable) before the first path. Any other argument starting with `-`, anywhere: stderr `vfind: unknown option ARG` (escaped) + `usage: vfind [-L] [PATH...]`, stdout empty, exit 1. Paths starting with `-` are given as `./-x`. | — (shell) |
| D20 | Totality? | The core never panics and terminates for every finite filesystem model (the loop rule bounds the depth by the number of distinct directory identities). | Verus total correctness |
| D21 | Trusted shell? | It writes each record/line exactly as produced by the core, plus nothing else; reviewed in the PR. | — (shell, reviewed) |

## Examples

Tree `t/`: regular files `t/b`, `t/.h`, `t/a-c`, `t/a/x`; directory `t/a`;
symlink `t/l → a`. Tree `u/`: symlink `u/up → ..` (back to `u`).
(⏎ = LF; stderr/exit shown when relevant.)

| #   | Command / input | Expected | Plausible wrong answer the spec must reject |
|-----|-----------------|----------|---------------------------------------------|
| E1  | `vfind t` | `t⏎t/.h⏎t/a⏎t/a/x⏎t/a-c⏎t/b⏎t/l⏎`, exit 0 | `…t/a⏎t/a-c⏎t/a/x⏎…` (globally sorted, not pre-order); `.h` missing; `t/l/x` listed (symlink followed) |
| E2  | `vfind -L t` | `t⏎t/.h⏎t/a⏎t/a/x⏎t/a-c⏎t/b⏎t/l⏎t/l/x⏎`, exit 0 | `t/l/x` missing; a loop error for `t/l` (it is not an ancestor of itself) |
| E3  | `vfind t/` | `t/⏎t/.h⏎t/a⏎t/a/x⏎…` | `t//.h` |
| E4  | `vfind` (cwd `t`) | `.⏎./.h⏎./a⏎./a/x⏎./a-c⏎./b⏎./l⏎` | `.h` without the `./` prefix; empty output |
| E5  | `vfind -L u` | stdout `u⏎u/up⏎`; stderr `vfind: filesystem loop: u/up⏎`; exit 1 | descending into `u/up` (`u/up/up⏎…`); `u/up` omitted; exit 0 |
| E6  | `vfind u` | `u⏎u/up⏎`, exit 0 | loop error (symlink isn't followed without `-L`) |
| E7  | model: directory `m` contains `b` whose identity equals `m`'s (bind-mount loop), no `-L` | `m⏎m/b⏎`, stderr `vfind: filesystem loop: m/b⏎`, exit 1 | entering `m/b` |
| E8  | `vfind t missing t/b` | stdout E1's lines then `t/b⏎`; stderr `vfind: missing: No such file or directory⏎`; exit 1 | exit 0; stopping at `missing`; a line for `missing` on stdout |
| E9  | dir `r` (unreadable, contains `s`) | stdout `r⏎`; stderr `vfind: r: Permission denied⏎`; exit 1 | `r` not printed; exit 0 |
| E10 | dir `d` with entry `a⏎b` (newline in name) | `d⏎d/a\nb⏎`: 2 lines for 2 paths | `d⏎d/a⏎b⏎`: 3 lines, forged path `b` |
| E11 | dir `d` with entries `x:`, `back\slash`, `café` | `d⏎d/back\\slash⏎d/caf\xc3\xa9⏎d/x\:⏎` | `d/x:` (unescaped marker); `d/back\slash` (collides with an escape); sorted after escaping |
| E12 | `vfind -L t` with extra broken symlink `t/dead → nowhere` | `t/dead⏎` among E2's lines (between `t/b` and `t/l`), exit 0 | an error line; exit 1 |
| E13 | `vfind -x t`; `vfind t -name a` | stderr `vfind: unknown option -x⏎usage: vfind [-L] [PATH...]⏎` (resp. `-name`); stdout empty; exit 1 | listing `t` anyway |
| E14 | `vfind t t/a` | E1's lines then `t/a⏎t/a/x⏎` | duplicates removed |
| E15 | core: directory `d` answers names `["b", "", ".", "..", "b", "x/y"]` | `d⏎d/b⏎` | `d/b` twice; `d/x/y` (forges a deeper path); an empty-name line `d/` |
| E16 | escaped path in stderr: unreadable dir `a: b` | stderr `vfind: a\: b: Permission denied⏎` | `vfind: a: b: Permission denied⏎` (ambiguous with a dir `a` and message `b: Permission denied`) |
| E17 | codec sanity: the table without the `:` rule | fails the library's `codec_conditions` (C4) | accepted |

(E8/E9 message texts come from the OS via the shell; the spec fixes only the
format around them.)

## Properties

- P1 **Exact count** (record safety): LF bytes in stdout == number of printed
  paths, so `vfind … | wc -l` is exact.
- P2 **No forged paths** (structure safety): stdout determines the printed
  path list; `decode_records::<BackslashEscape>(stdout) == Some(paths)`.
- P3 **No duplicates per start path**: within one start path's listing no
  path is printed twice (D6 makes this hold even for a misbehaving shell).
- P4 **Pre-order**: every printed path other than a start path comes after
  its parent directory's path, within the same start path's listing.
- P5 **Determinism**: output, stderr and exit code are a function of the
  arguments and the filesystem model.
- P6 **Termination**: the walk terminates on every finite filesystem model,
  with or without `-L`.
- P7 **Errors ⇔ exit 1**: the exit status is 1 iff stderr is non-empty.

## Not verified

- The trusted shell: argv parsing (D19), the `.` default (D5), the
  `stat`/`lstat`/`readdir` answers and OS error texts, writing bytes. Covered
  by review (no traversal, sorting, filtering or escaping logic in the shell),
  runtime tests, and a **differential test**: `cargo test` builds a temp tree
  of plain-ASCII names (files, dotfiles, nested dirs, a symlink to a dir, a
  `-L` loop, a broken symlink, an unreadable dir) and checks that `vfind`'s
  set of stdout lines equals GNU `find`'s (`find -L` for `-L`), and that the
  order matches D4. Skipped if GNU `find` isn't installed.
- The filesystem doesn't change during the run (D3); concurrent changes may
  produce output that matches no single snapshot.
- Relative interleaving of stdout and stderr.
- Performance and memory for huge trees: by review.
- Deliberate differences from GNU `find`: escaping (D13, including `:`),
  byte-sorted order (D4), message wording and the `vfind:` prefix (D10, D17),
  no expressions (D1).
